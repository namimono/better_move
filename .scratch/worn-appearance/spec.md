# 推进器穿戴外观

**Status:** ready-for-agent

## Problem Statement

推进器护腿装备到身上后没有穿戴外观，玩家与旁观者都看不见装备；物品栏图标引用的贴图也缺失。不同等级应能从外观上区分，且护腿槽与 Trinkets 饰品槽装备时都应可见。

## Solution

为在用的五档推进器护腿（铜、铁、金、钻石、下界合金）提供统一推进器剪影的原版护甲感 2D 穿戴外观；物品栏继续使用既有图标资源（可不与穿戴外观风格统一）。护腿槽与饰品槽装备时都绘制；外观只由等级决定；不提供护甲值；不随升级项或推进/蓄力/过载状态变化。穿戴美术先占位后由代理用 Blockbench 出图替换。

## User Stories

1. As a 玩家, I want 把推进器装进护腿槽后腿上能看见穿戴外观, so that 我知道装备已生效且外观像护腿。
2. As a 玩家（已安装 Trinkets）, I want 把推进器装进饰品槽后也能看见同一套穿戴外观, so that 与原版裤子并存时推进器仍然可见。
3. As a 玩家, I want 铜 / 铁 / 金 / 钻石 / 下界合金五档的穿戴外观材质不同但剪影一致, so that 我能辨认等级又认得这是推进器。
4. As a 玩家, I want 物品栏里也能看到对应等级的物品栏图标且不再是紫黑块, so that 未装备时也能辨认物品。
5. As a 玩家, I want 安装任意升级项后穿戴外观不变, so that 外观只表达等级，升级能力仍由 tooltip / HUD 表达。
6. As a 玩家, I want 推进、蓄力、过载时穿戴贴图保持静态, so that 动态反馈继续来自粒子、音效与 HUD，外观不闪乱。
7. As a 生存玩家, I want 增加穿戴外观后护甲值与现在一致（仍无护甲加成）, so that 战斗平衡不被这次外观改动牵连。
8. As a 旁观玩家, I want 看到其他玩家穿着对应等级的推进器外观, so that 多人时等级可辨。
9. As a 模组维护者, I want 正式贴图可只替换 PNG 而不改渲染逻辑, so that 占位接线与出图可以分开迭代。

## Implementation Decisions

- 视觉形态：原版护甲感 2D 贴图层（非自定义立体模型）。见访谈共识。
- 双槽渲染：护腿槽与 Trinkets 饰品槽都绘制穿戴外观。见 ADR-0002。
- 剪影策略：五档共用推进器剪影，仅材质色与纹路随等级变化。
- 外观驱动：只跟等级走；与已装升级项无关；推进/蓄力/过载不换贴图。
- 数值：不加护甲值；保持非防护装语义。见 ADR-0001。
- 资源范围：仅铜、铁、金、钻石、下界合金；木/石不在本次（注册仍注释掉）。
- 资源内容：每档一份穿戴外观贴图；物品栏图标沿用既有 `textures/item/booster_leggings_*.png`，不强制与穿戴外观同风格。
- 美术流程：先占位贴图接通渲染，再由代理用 Blockbench 按护甲 UV 绘制并导出穿戴外观 PNG 替换；物品栏图标不纳入 Blockbench 重绘。
- 模块：新增「等级 → 穿戴/物品栏贴图定位」模块作为主测试接缝；客户端在护腿装备路径与 Trinkets 饰品渲染路径消费该定位；物品 model 继续指向物品栏图标路径。
- 不把推进器改成带护甲值的护甲物品来「顺便」获得渲染；渲染与防护属性解耦。

## Testing Decisions

- 测试验证可观察行为，不绑死 mixin / 渲染器内部结构。
- 主接缝：等级 → 贴图资源定位（单元测试覆盖五档路径正确且互异；与升级项无关）。
- 回归：装备推进器后仍不提供护甲属性（ADR-0001）。
- 画面本身：人工用客户端验收——五档可见、两槽都画、饰品槽与原版裤并存、无紫黑缺失贴图。
- 参考现有纯逻辑单测风格（如蓄力会话、推进破击伤害测试），为定位模块补充同风格测试。

## Out of Scope

- 自定义 3D 立体推进器模型
- 木 / 石等级的穿戴外观与物品栏图标
- 按升级项或蓄力/过载切换贴图、发光层
- 增加或调整护甲值、韧性等防护属性
- 饰品与原版裤叠穿时的高级分层/半透明/防 Z-fighting 精修
- 推进时的额外贴图动画
