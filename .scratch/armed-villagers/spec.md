# 武装村民

Status: ready-for-agent

## Problem Statement

当前推进器只能由玩家通过按键使用。村民虽然会拾取少量原版物品，却不会拾取并装备推进器或剑，也不会在装备齐全后使用推进器追击、持剑攻击玩家。玩家希望通过向村民投放装备，直接形成一种简单、可观察的武装村民玩法，而不引入新的职业、驯服、阵营或复杂升级 AI。

## Solution

允许原版成年村民在 `mobGriefing` 开启时拾取地面的推进器与剑，并在对应装备槽为空时立即装备。推进器已穿在护腿槽且剑已拿在主手后，村民成为武装村民：在非和平难度下锁定附近可攻击玩家，暂时中断普通日程进行追击和村民剑击，并在合适距离自主触发基础村民推进。

村民推进使用推进器等级自带的基础能力，不应用已安装升级项或玩家技巧；采用固定发起方向、简单冷却和耐久消耗。任一必需装备缺失后，村民立即停止交战并恢复普通村民行为。

## User Stories

1. As a 玩家, I want 成年村民拾取我丢在地上的推进器, so that 我可以通过游戏内物品交互让村民获得推进能力
2. As a 玩家, I want 成年村民拾取我丢在地上的剑, so that 我可以让村民获得近战能力
3. As a 玩家, I want 村民拾取推进器或剑后立即装备到护腿槽或主手, so that 装备状态立即且可预测地生效
4. As a 玩家, I want 已占用对应装备槽的村民拒绝同类物品, so that 村民不会反复替换或吞掉装备
5. As a 玩家, I want 村民只有同时穿戴推进器并主手持剑时才成为武装村民, so that 单件装备不会意外触发攻击
6. As a 玩家, I want 职业村民、无业村民和傻子村民都能成为武装村民, so that 该玩法不依赖职业
7. As a 玩家, I want 幼年村民、流浪商人、僵尸村民及其他类人生物不进入武装状态, so that 功能保持在明确的核心范围
8. As a 生存或冒险玩家, I want 武装村民锁定并攻击附近的我, so that 装备齐全会产生明确的敌对结果
9. As a 创造或旁观玩家, I want 武装村民忽略我, so that 我可以安全测试、观察或建造
10. As a 玩家, I want 武装村民首次从 32 格内当前可见的可攻击玩家中选择最近者, so that 它不会隔墙或从过远位置突然锁敌
11. As a 玩家, I want 武装村民短暂失去目标视线后仍能正常绕路追击, so that 简单遮挡不会立即清除追击
12. As a 玩家, I want 目标失效或超过 48 格时武装村民放弃追击, so that 它不会无限跨区追杀
13. As a 玩家, I want 目标在 48 格内但连续 10 秒既不可见又无法接近时武装村民放弃追击, so that 它不会永久卡在不可达目标上
14. As a 玩家, I want 武装村民交战时暂停工作、睡眠、社交、恐慌和交易, so that 战斗行为不会被普通村民日程打断
15. As a 玩家, I want 武装村民脱离追击后恢复原本日程, so that 获得装备不会永久破坏村民职业与生活行为
16. As a 玩家, I want 和平难度下武装村民保留装备但不锁敌、追击或推进, so that 和平模式保持安全
17. As a 玩家, I want 武装村民用剑进行普通近战攻击, so that 不需要玩家攻击输入也能造成可靠伤害
18. As a 玩家, I want 村民剑击以 1 点基础攻击力加主手剑的原版属性与附魔修正计算, so that 不同剑和附魔仍有意义
19. As a 玩家, I want 村民剑击每 20 tick 最多发生一次且成功命中消耗剑 1 点耐久, so that 攻击频率与装备成本可预测
20. As a 玩家, I want 村民剑击不触发玩家专属暴击、横扫或推进破击, so that 核心功能不扩张成第二套玩家战斗系统
21. As a 玩家, I want 武装村民在目标可见、前方无明显固体阻挡且距离为 6～20 格时使用村民推进, so that 它能主动缩短中距离
22. As a 玩家, I want 武装村民不足 6 格时使用普通近战追击、超过 20 格时先寻路接近, so that 推进不会贴脸乱飞或远距离失控
23. As a 玩家, I want 村民推进只能从地面触发且不能在液体、载具或拴绳状态下触发, so that 物理边界保持简单
24. As a 玩家, I want 村民推进在发起时锁定一次方向且不在途中追踪我, so that 横向躲避有意义且行为容易理解
25. As a 玩家, I want 村民推进碰到固体障碍或进入水、熔岩时结束, so that 推进不会卡进障碍或液体
26. As a 玩家, I want 村民推进期间仍可在正常近战距离执行村民剑击, so that 成功接近目标可以转化为攻击
27. As a 玩家, I want 村民推进和身体碰撞本身不造成伤害, so that 伤害来源始终是可理解的剑击
28. As a 玩家, I want 每次村民推进消耗推进器 1 点耐久并进入 60 tick 冷却, so that 村民不能无限连续推进
29. As a 玩家, I want 村民推进不消耗或检查村民食物库存, so that 不需要新增村民饥饿系统
30. As a 玩家, I want 村民推进只使用推进器等级自带的基础能力, so that 已安装升级项和 Hyper 不需要复杂的村民 AI
31. As a 玩家, I want 村民推进期间不累计坠落距离、结束后恢复原版坠落累计, so that 推进自身通常不会误伤村民但高处坠落仍有风险
32. As a 附近玩家, I want 听到基础推进世界音效并看到云雾轨迹, so that 村民推进是可感知的
33. As a 玩家, I want 村民推进不发送玩家专属 HUD、镜头、冷却或第一人称反馈, so that 我的界面不会误认为自己正在推进
34. As a 玩家, I want 推进器或剑损坏、移除或离开规定槽位后村民立即退出武装状态, so that 敌对状态始终对应当前装备
35. As a 玩家, I want 推进器耐久耗尽后进行中的能力结束且村民停止攻击, so that 已失去推进器的村民不会残留武装行为
36. As a 玩家, I want 武装村民死亡时推进器和剑必定原样掉落, so that 当前耐久、附魔和推进器升级项不会被随机吞掉
37. As a 服务器管理员, I want `mobGriefing=false` 时禁止村民新拾取推进器和剑, so that 可以沿用原版规则关闭该入口
38. As a 服务器管理员, I want 关闭 `mobGriefing` 不强制卸下村民已有装备, so that 游戏规则变化不会破坏实体已有状态
39. As a 模组兼容玩家, I want `swords` 标签内的其他模组武器也被识别为剑, so that 正确声明标签的剑可以参与该玩法
40. As a 装备投放者, I want 自己不因提供装备而获得友军豁免, so that 武装村民按统一规则攻击所有可攻击玩家

## Implementation Decisions

1. **实体范围**：仅原版成年 `Villager`。职业村民、无业村民和傻子村民均支持；幼年村民、流浪商人、僵尸村民、女巫及其他实体不支持。
2. **武装判定**：武装村民是实时派生状态，不写永久标签。护腿槽必须是本模组推进器，主手必须是属于 Minecraft 通用 `swords` 物品标签的物品；任一条件不满足便立即退出。
3. **装备拾取**：扩展村民现有拾取逻辑而不替换食物、种子和职业物品行为。仅在 `mobGriefing` 开启且对应槽为空时拾取推进器或剑；拾取后直接放入护腿槽或主手，不先进入内部物品栏，不自动比较或替换装备。
4. **装备持久化与回收**：使用实体原生装备槽保存装备。通过拾取获得的推进器和剑设为必定掉落；掉落保留完整物品数据。
5. **战斗控制**：新增服务端武装村民战斗控制模块。它根据实时装备、难度和目标有效性临时接管导航与攻击；无目标或退出武装状态时归还普通村民日程。各村民独立运行，不共享目标或协同。
6. **目标资格**：仅存活、处于生存或冒险模式且可被实体正常攻击的玩家。创造、旁观、死亡或其他不可攻击玩家无效。装备投放者没有所有权或友军豁免。
7. **锁敌与脱离**：首次锁敌选择 32 格内当前可见的最近可攻击玩家；锁定后允许短暂失去视线并继续寻路。目标失效或超过 48 格立即脱离；在范围内连续 200 tick 既不可见又无法接近也脱离，然后可重新锁敌。
8. **行为优先级**：交战暂时中断工作、睡眠、社交、恐慌和交易；脱离追击后恢复原本日程。和平难度禁用锁敌、追击、村民推进和村民剑击，但不解除装备。
9. **剑识别与伤害**：统一使用 `swords` 物品标签识别剑。为村民提供 1 点基础攻击伤害能力，使主手剑的原版属性修正可参与计算；附魔走原版近战伤害修正。攻击间隔 20 tick，成功命中按原版剑行为消耗 1 点耐久。
10. **攻击范围**：村民剑击使用原版生物近战可达判断与攻击调用；不实现玩家暴击、横扫、攻击蓄力、推进破击叠层或碰撞伤害。
11. **村民推进模块**：新增仅服务端的村民基础推进运行器，复用推进器等级的平衡参数、基础世界音效和云雾轨迹；不依赖客户端按键、C2S 网络包、玩家饥饿、玩家冷却容器或玩家反馈包。现有玩家推进路径保持行为不变。
12. **触发条件**：仅交战中的武装村民可以触发；必须脚踏地面、目标可见、距离闭区间为 6～20 格且朝目标方向无明显固体阻挡。空中、水中、熔岩中、乘坐载具或被拴住时不触发。
13. **方向与结束**：发起时以目标当前位置计算并锁定一次方向，推进期间不持续追踪。固体碰撞、进入水或熔岩、实体死亡/卸载/转换、失去推进器或其他非法生命周期状态会结束推进。液体和身体碰撞不造成额外伤害。
14. **推进与攻击并行**：推进期间仍按普通 20 tick 间隔检查村民剑击；进入近战范围后可命中目标，推进本身不改变攻击间隔。
15. **资源**：每次成功发起推进立即损耗推进器 1 点耐久，并以村民自身为单位记录 60 tick 服务端冷却；不读取或消耗村民食物库存。推进器损坏后重新计算武装状态。
16. **升级项边界**：村民推进忽略所有已安装升级项，包括空中推进、无冷却、随机冲量、垂直起飞、遁地、推进破击和过载蓄力；也忽略玩家技巧 Hyper。推进器上的升级数据仍随物品保存和掉落。
17. **运动安全**：推进持续期间清除累计坠落距离；结束后恢复原版坠落累计。服务端负责速度更新和同步。
18. **反馈**：复用世界可见的基础推进音效与云雾轨迹。不得向任何玩家发送“自己推进”的 HUD、镜头震动、冷却或第一人称反馈。
19. **客户端范围**：不新增村民专用推进器穿戴外观、持剑姿势或挥剑动画。原版装备同步和原版村民渲染能自然显示的内容可以保留，但不作为验收条件。
20. **领域用词**：规格与实现使用 `CONTEXT.md` 中的武装村民、村民推进、村民剑击、可攻击玩家、锁敌、脱离追击和交战；避免用“战斗职业”“永久敌对”或“冲撞伤害”表达本功能。

## Testing Decisions

1. 测试验证外部可观察的游戏行为，不断言 mixin 注入点、Brain 内部内存布局、控制器私有状态或运动运行器内部集合。
2. 主要测试接口是 **Fabric 服务端 GameTest 世界场景**。测试在真实 `ServerLevel` 中生成村民、地面物品和模拟服务端玩家，通过实体公开状态与世界结果观察装备槽、当前目标、位置/速度、生命值、耐久、掉落物和行为恢复。
3. 不为测试新增专用业务 API。若实现中自然形成纯规则策略，可以补充 JUnit 单元测试，但它不是替代 GameTest 的主验收接口。
4. GameTest 至少覆盖：推进器/剑分别拾取并立即装备；槽已占用时拒绝替换；两件齐全后锁敌；缺失任一装备后停止；创造/旁观/死亡玩家无效；和平难度不交战；`mobGriefing=false` 禁止新拾取。
5. GameTest 至少覆盖：最近可见玩家锁敌；32 格外不首次锁敌；48 格外脱离；连续 200 tick 不可见且无法接近后脱离；交战时追击与村民剑击；脱离后不再保持攻击目标。
6. GameTest 至少覆盖：6～20 格地面村民推进；过近、过远、空中、液体、载具、拴绳和前方阻挡时不发起；发起方向固定；固体碰撞或进入液体后结束。
7. GameTest 至少覆盖：推进消耗 1 点耐久、60 tick 内不重复发起、冷却后可再次发起、推进期间不累计坠落距离、推进结束后恢复原版坠落规则。
8. GameTest 至少覆盖：村民剑击使用剑与附魔修正、20 tick 攻击间隔、成功命中消耗耐久、推进期间可剑击、推进/碰撞无额外伤害。
9. GameTest 至少覆盖：推进器升级项不改变村民推进路径；装备损坏后退出武装状态；死亡时两件装备保留完整物品数据并必定掉落。
10. 世界音效和云雾轨迹通过一次人工服务端冒烟验收；不要求像素级、声音事件监听或客户端截图自动化测试。
11. 参考仓库现有纯 JUnit 测试的断言风格，但实体生命周期与 AI 行为必须以 GameTest 为准。构建应继续通过现有 `test` 任务，并新增可重复运行的 GameTest 运行入口。

## Out of Scope

- 村民专用推进器穿戴外观、持剑姿势、挥剑动画或其他客户端渲染
- 村民使用任何推进器升级项或玩家技巧 Hyper
- 村民蓄力、遁地、过载爆炸、垂直起飞、空中推进或推进破击
- 碰撞伤害、横扫、暴击、攻击叠层或玩家攻击蓄力
- 装备品质比较、自动换装、自动升级或从内部物品栏择优装备
- 装备所有权、投放者豁免、驯服、阵营、友军或声望系统
- 多个武装村民共享目标、传播仇恨、同步推进或战术协同
- 新村民职业、交易内容、生成规则、自然携带装备或合成配方
- 流浪商人、幼年村民、僵尸村民、女巫或其他生物支持
- 改变现有玩家推进、玩家网络协议、HUD、镜头与升级项行为
- 为声音和粒子建立客户端自动化或专用网络反馈协议

## Further Notes

- 本规格来源于已结束的 `grill-with-docs` 会话，目标是交付核心功能；未确认的额外玩法一律不因实现便利而加入。
- 当前推进触发、持续运动、冷却、饥饿与推进破击均显著依赖 `ServerPlayer`。村民路径应保持服务端独立，并只共享稳定的等级平衡与世界反馈能力，避免扩大玩家路径的回归面。
- 当前村民原版拾取入口会把其想要的物品放入内部物品栏；推进器和剑需要走装备槽专用分支，同时保留原版想要物品逻辑。
- 仓库已有 JUnit 5，但当前没有实体 GameTest。Fabric API 和 Minecraft 1.21.1 已提供 GameTest 能力、真实实体生成、地面物品生成与模拟服务端玩家支持。
