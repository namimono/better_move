# Charge and overload feedback acceptance bar

Type: grilling  
Status: resolved  
Blocked by: 01  

## Question

「人物与 UI 要有蓄力 / 过载表现」要决策到哪一层才算 destination 满足？

钉死 **验收条**（实现必须满足的最低反馈），例如：

- UI：是否要进度条 / 沿用现有 CD HUD 变体 / 仅准星或文字
- 人物：粒子、发光、抖动、视角倾斜等哪些是 P0
- 蓄力 vs 过载的 **可区分** 信号（颜色、节奏、音效）
- 哪些明确留给实现自由发挥，不在 map 阻塞

可选：若「观感应先看一眼」才敢定，升级为 prototype 票并链原型资产。

## Answer

### P0（实现必须满足）

1. **主通道**：热键栏旁推进 HUD **同一阅读区**的蓄力进度条；与现有 CD | 耐久 | 破击 同区阅读。
2. **不准星**：不在准星处做蓄力/过载功能或进度。
3. **单条两段色**：一条进度表达蓄力时长 → 过载窗口（蓄力段一色填满，过载切第二色，可加脉冲）。
4. **显隐**：仅在蓄力过程中显示该轨（含过载窗口）；未按住不占位。
5. **出场/退场动效**：必须有可感知的淡入淡出和/或放大缩小；禁止硬切出现/消失（便于玩家把「我在蓄力」与该轨绑定）。
6. **人物粒子**：蓄力与过载可区分（第三人称/他人可见）；发光、镜头抖、FOV、音效细节 **非 P0**。
7. **过载爆炸反馈**：沿用原版 `explode` 声画即可；不另定爆炸专用 VFX / 自伤闪屏。

### 实现自由（不挡 map / 不挡验收）

- 具体色值、粒子种类与密度、动效曲线与时长
- 蓄力条相对 CD|耐久|破击 的精确像素布局
- 发光、镜头抖、FOV、蓄力循环音效
- 正式贴图/音效素材管线
- 爆炸额外 UI

### 不升级

- 不需要单独 prototype 票；本验收条足够实现 session 开工。
